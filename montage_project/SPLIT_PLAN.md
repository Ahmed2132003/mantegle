## 3. Circular-dependency risks (measured)

Naive assignment by name gives ONE big cycle (render, split, draw, t1, t2, templates, ask). Resolutions already baked into `plan_map.json`:

| edge | cause | resolution |
|---|---|---|
| split -> render / t1 | `make_split_background` calls `_draw_frame` (render) and `make_tech_background` (t1) | move `make_split_background` into `templates/t1_tech` (it only serves T1); `split` becomes a pure leaf |
| draw -> t2 | `t2_rgb` default arg `T2_ACCENT`; `t2_fit_text` uses `t2_size_for_cap` | put `T2_ACCENT` in `common`; `t2_size_for_cap` goes to `draw` (generic) |
| ask -> templates / t2 | `interactive`/`_interactive_core` call `choose_template`, `_interactive_t2`, t2_ask_* | move `interactive`, `_interactive_core` into `templates/__init__` (orchestrators); `ask` keeps only generic prompts |
| t1/t2 -> templates/__init__ | `maybe_save_template`, `list_templates`, `_saved_templates`, `_PRESET`, `_tpl_template_id` used by ask_template/t2_ask_config | move these 5 into `ask` (leaf) |
| t2 -> t1 | `t2_build_items` calls `t1_build_items`; `t2_ask_cards_cfg` uses `ICON_LINE` | `ICON_LINE` -> `ask`; `t2_lime` may import `t1_tech.t1_build_items` (one-way, acceptable) - better: extract shared part in S3 |

**Residual cycle (unavoidable without a hook):** `render` <-> `templates/*`.  render calls `get_template` (4 sites: build_items, preflight_cfg, render, render_still) plus direct `t2_caption_items` (build_items) and `t2_prepare_card_layers` (render); t1/t2 call back `_draw_frame` / `_first_frame`. Fix in S2/S3: in `render.py` import the registry **inside the functions** (`from mt.templates import get_template`), keep templates importing `render` at top level. Do not add new hooks to the registry in S2 (that would change behaviour); the two direct t2 calls become lazy imports until S3.

## 5. Path / cwd risks

- `BASE = Path(__file__).resolve().parent` (line 82) feeds `TEMPLATES_DIR`, `FONTS_DIR`, `DEFAULTS_FILE`, `_find_tool` (looks in `BASE`, `BASE/ffmpeg/bin`, `BASE/bin`), `GOLDEN_DIR` (selftest_golden), and `main`-time check `str(FFMPEG).startswith(str(BASE))` (line 6727). **Once `BASE` lives in `mt/common.py`, `__file__.parent` would be `mt/`: wrong.** Using `sys.argv[0]` instead is also fragile (breaks when imported by tests/tools). Recommended: `Path(__file__).resolve().parent.parent` in `mt/common.py` (package folder is always directly under the script folder), plus an assertion `(BASE/'montage.py').exists()` in selftest.
- Self-references via `__file__`: line 5343 (compiles its own source - check 46) and the subprocess re-invocations at 5470, 6048, 6057, 6506, 6722, 6811. After the split `__file__` in `mt/selftest.py` points at the wrong file: use `BASE / 'montage.py'`. Test 46 (`py_compile` of itself) must compile **all** of `mt/*.py` too.
- `selftest_golden/` and the new `selftest_golden_t2/` are located via `BASE` - keep them next to `montage.py`, not inside `mt/`.
- Defaults file `montage_defaults.json` and `templates/*.json` are `BASE`-relative (not cwd): fine, no `os.getcwd()` use anywhere (0 hits). `clean_path` uses `os.path.abspath` = cwd-relative for user input only.
- Package name clash: the **`templates/` data folder** (saved JSON presets, `TEMPLATES_DIR = BASE/'templates'`) vs the planned python package `mt/templates/`. Different parents (`BASE/templates` vs `BASE/mt/templates`) so it works, but never `sys.path`-insert `BASE/mt` and keep the names distinct in docs.
- Import-time side effect: line 129 `_ensure_python_packages()` (interactive pip prompt!) runs on import. It must remain in `common.py` executed before Pillow/arabic imports, and `import mt.*` from tools/tests will trigger it (seen: `--help` prompts to install). Consider an env opt-out in S1 (behaviour-neutral default).

## 6. Other findings

- Names mislead: ~30 `t2_*` helpers (masks, gradients, glow, shear, rrect, text_mask) are generic Pillow code -> `draw.py`, not the T2 module. Keep their names (compat) in S1; optional alias rename later.
- `TEMPLATE_REGISTRY` entry 3 (Custom) shares T1 callbacks with entry 1 - keep both in `templates/__init__`, ask_template/ask_hud_template live in `t1_tech`.
- `render` (98 lines) + `build_ffmpeg_cmd` (146) hold the ffmpeg expression building inline; `anim.py` as specified gets only easing/`anim_state` in S1. Extraction of expression builders would need a code change (not a move) - deferred past S4 or done as an explicit S2b.
- Job save/load is split: `_load_job` (7 lines) is a function but *saving* is inline in `_main` (twice) and `_interactive...` -> `render.py` gets `_load_job`; add `save_job()` only if allowed to change code (not a pure move).
- Selftest is ~1,580 lines (23% of the file) and re-invokes the script via subprocess 6 times (lines 5470, 6048, 6057, 6506, 6722, 6811); it moves last, and cannot affect rendering - but see the `globals()` patching risk in section 4.
- Baseline test flake: check #26 (T1 vs T2 render time ratio <= 1.30) fails on this machine (1.35-1.38x) before any change - environmental, not a regression.
